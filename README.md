# State of AI: alternative visual narrative

This is an **alternative development version**, not a production release. It preserves the original cover, graphics, animations and interactive exploration while arranging the report into seven chapters and retaining the 18-slide deck.

## Branch and release boundary

- **Working branch:** `alternative/visual-narrative`.
- **Production line:** `main` is unchanged by this branch.
- **No deployment:** Pushing or checking out this branch is not approval to merge or deploy it. No production deployment is part of this handoff.
- **Firebase warning:** The existing Firebase configuration still names the production project `state-of-ai-dvc`. Do not run `firebase deploy` from this branch without explicit release approval.
- **Original version:** `versions/pre-seven-chapters/` contains the preserved original web source. Do not edit it to update the alternative; its 107 files are checked against a checksum manifest.

## Run locally

Requirements: Python 3.10+, Node.js 18+, Bash, and `rsync`. No Perplexity account, API credentials, local backup tags or external runtime API are needed.

```bash
git clone --branch alternative/visual-narrative \
  https://github.com/DVC-Agent/state-of-ai.git
cd state-of-ai

python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements-dev.txt

bash audit/build_preview.sh
python3 audit/test_visual.py
node hc_microcopy_tests.js

python3 -m http.server 8000 --directory ../state-of-ai-preview
```

Open `http://localhost:8000/index.html` for the report or `http://localhost:8000/slides.html` for the deck. The build writes the generated English pages in the checkout and copies a static preview into the sibling folder `<checkout>-preview`; `PREVIEW_DIR` can override that destination, but it must be outside the checkout.

The alternative can also be viewed directly from the checked-in files:

```bash
python3 -m http.server 8000
```

## Where to edit

- **Report sequence and copy:** `audit/build_visual_revision.py`.
- **Deck sequence and copy:** `audit/build_visual_deck.py`.
- **Shared facts and qualifications:** `facts-data.js`, `narrative-data.js`, and `evidence-additions-data.js`. Keep repeated figures aligned across text, charts, tooltips and disclosures.
- **Visual presentation and interaction:** `visual-edit.*`, `visual-deck.*`, `visual-charts.js`, and `evidence-visuals.*`, alongside the retained original assets and modules.
- **Explorer data:** `healthcare-data.js`, `robotics-data.js`, `industrial-data.js`, and `services-matrix-data.js`.
- **Build inputs:** `audit/inputs/` contains the checked-in evidence snapshot, incumbent records and original-source checksums. The current visual builders do not require the original session's Git refs.

`index.html`, `slides.html`, `whats-new.html`, `app.js`, `slides.js` and `sec8.js` are regenerated by the visual build. Put durable changes in their corresponding builders, inputs or overlay modules rather than hand-editing generated output.

The older prose-first builders and their QA records remain as historical work. `audit/build_preview.sh` uses the current visual builders; do not use `build_narrative.py` or `build_deck.py` for this alternative version.

## Review before a future release

- Preserve the original title/cover and visual inventory; use the tests as a regression check.
- Keep the concise reading path and click-through evidence. Do not replace the graphics with long text sections.
- Distinguish reported revenue, annualized pace, transaction marks, historical observations, forecasts and modeled allocations.
- For the new benchmark and compute views, keep missing results distinct from zero and retain both estimated-quarter labels.
- The bear-case slide is deliberately deferred.
- Only merge to `main` or deploy to production after explicit approval.

The release notes and coverage are in `audit/RELEASE-VISUAL.md`, `audit/QA-INVENTORY-VISUAL.md`, and the recorded browser results. Primary-source notes for the added evidence are in `audit/ADDED-EVIDENCE-2026-10-16.md`.
